# START HERE

Source for the START HERE Google Doc on the Skills Hub drive. The user connects Google Drive,
then tells their agent: *"Read the START HERE doc on the Skills Hub drive and follow it."*
This doc is prose, so reading it with `read_file_content` is fine. Every package file is
fetched with `download_file_content`.

**Claude Science reads this first.** Its sandbox gives every cell a fresh home directory, so nothing under `~` survives
to the next step; only the workspace directory persists. Pick the root `<workspace>/.skills-hub` (the absolute path
from `os.getcwd()` in the kernel), export `SKILLS_HUB_ROOT=<that path>` in every shell cell, and read every
`~/.skills-hub` below as that root (the tools default to `SKILLS_HUB_ROOT` when it is set). The Drive connector runs
in the kernel: a download arrives as a Python value, so decode its `content` there and write the bytes to disk;
the "zip came back inline" rule in step 3 is for Claude Code and does not apply. The sandbox sets `PYTHONSAFEPATH`,
which the tools tolerate; run them as `python3 <root>/framework/current/tools/<tool>.py`.

1. Confirm Google Drive is connected for this host. Cursor: that is Google's Drive MCP server in `~/.cursor/mcp.json`, authenticated on its Local row (see hosts.md), not Cursor's Google Drive plugin, whose sign-in never completes.
2. Claude Science: set the `skill_edit` and `skill_publish` grants from the host (see hosts.md). Claude Code and Cursor: get `uv` and choose the tool command, as follows.
   - Look first and change nothing: `uv --version`, `~/.local/bin/uv --version`; on a Mac also `sw_vers -productVersion`, `uname -m` and `xcode-select -p`.
   - No `uv`: ask the user, then install it into their home folder, stopping at the first route that works. First the official installer, `curl -LsSf https://astral.sh/uv/install.sh | sh` (it writes `~/.local/bin/uv`); if that is blocked (a proxy, security software), `brew install uv`, but only when `brew --version` already works. If both fail, stop and tell the user what each said; try nothing else. Never `sudo`, never write outside the home folder, never run anything that opens a system dialog or asks for an administrator password. A new `uv` is not on the `PATH` until a new shell: call it as `~/.local/bin/uv` for the rest of this install.
   - The tool command. Every step below runs a Skills Hub tool as `python3 <tool>.py`. Use `python3` only when `python3 --version` prints Python 3.9 or later. On a Mac where `xcode-select -p` fails, never run `python3` at all: without Apple's Command Line Tools it opens their install dialog, which can need an administrator. In both other cases run the same tool, with the same arguments, as `uv run --python-preference only-managed --script <tool>.py` (`uv` fetches its own Python into the home folder; no administrator).
3. Download the Skills Hub `current.json` by file ID `<SKILLS_HUB_CURRENT_JSON_ID>`, then the zip by its `zip_file_id`. A `current.json` comes back inline; read it from the decoded base64 `content`. A zip is saved by the host to a file. Never retype a zip's base64. If a zip comes back inline in Claude Code, stop and tell the user to add `"env": {"MAX_MCP_OUTPUT_TOKENS": "2000"}` to their Claude Code settings and start a new session.
4. The saved file is JSON. Decode its `content` field from base64 and check the sha256 of the result against `zip_sha256` (`shasum -a 256`, or `certutil -hashfile <file> SHA256`). On a mismatch, retry once, then stop.
5. Unzip into `~/.skills-hub/framework/current/`, then delete `padding.bin` from it.
6. Download `index.json` by file ID `<INDEX_JSON_ID>`. For the foundation package and each domain package the user names, download its `current.json` and zip, then run `python3 ~/.skills-hub/framework/current/tools/install.py --package <slug> --sha256 <zip_sha256> --bytes <zip_bytes> --version <version> --current-file-id <id> --from-tool-result <saved zip file>` (that file may be the host's saved JSON result, the zip's own bytes, or base64 of them).
7. Load the skills into the host.
   - Claude Code: `install.py` wrote `~/.skills-hub/.claude-plugin/marketplace.json`. Register it once and install each plugin: `claude plugin marketplace add ~/.skills-hub`, then `claude plugin install skills-hub@skills-hub` and `claude plugin install <slug>@skills-hub` for each package. Add these to the `permissions.allow` list in `~/.claude/settings.json`, with `~` written out as the absolute home directory in the second line: `Bash(uv run --script ~/.skills-hub/*)`, `Bash(uv run --script /home/<user>/.skills-hub/*)`, `Read(~/.skills-hub/**)`. Later installs and syncs need no new registration: the marketplace file is rewritten and swapping `current` is the update.
   - Cursor: run `python3 ~/.skills-hub/framework/current/tools/link.py`.
   - Claude Science: publish each skill with `host.skills` (`edit` each file byte for byte, then `publish`), from the framework's `skills/` and each package's `skills/`. A skill already published under the same name (an earlier install) is replaced by editing and publishing again; delete it first only if its file set shrank. Every write raises one approval card unless the two grants are set, so a package of N files costs N+1 cards without them. The published copies are read-only; the install root under the workspace is what `sync` updates and what the scripts' sync gate reads through `SKILLS_HUB_ROOT`.
8. Run `python3 ~/.skills-hub/framework/current/tools/doctor.py` (`python` on Windows) and tell the user, in plain language, the Skills Hub version, each package version, and any blocked skill name.
9. If any step above was not smooth (a retry, a hash mismatch, a zip that came back inline, a `uv` install that needed a workaround, a step you or the user had to do differently from how it is written here, or a blocked skill), that is a call for feedback. On a Mac, offer it even when every step was smooth (Mac installs are not measured yet), with `--worked yes` if they were, and put in the note the macOS version, the chip, how `uv` was found or installed, and which tool command ran. Tell the user what went wrong in one or two sentences and offer to record it. With their consent, run `python3 ~/.skills-hub/framework/current/tools/feedback.py --dest <feedback-dir> --package skills-hub --skill install --version <Skills Hub version from doctor> --author <email> --question "First install from START HERE" --worked no --note "<what went wrong and what you did instead>" --consent` and upload the JSON file with `create_file` to the foundation package's `feedback/` folder. Do not write anything without consent.

Later updates use the `sync` skill. A package's scripts refuse to run when its last check is over 24 hours old or an update is pending; sync it, then run the script again.
